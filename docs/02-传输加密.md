# 02 · 传输加密（完整推导链）

## 0. 结论

```
算法   : AES-128-ECB / PKCS7
密钥   : MD5("haha") = 4e4d6c332b6fe62a63afe56171fd3725
信封   : base64( ciphertext )          请求体、响应体同构
承载   : libsafe_auth.so（arm64，156 KB）
```

实测样本：

```
GET  /api/iap3/user/queryAccountInfo
  ← 5K+P24pJ1aqpJvd+/CuSfZ4RgrYpeutuzNTbvk7asHc=
  解密 → {"code":-1,"message":"failed"}

POST /api/ai2/video/task/create  {}
  ← U4lXt1TANIhd8Nh5mZb6e3wUatN8+I2QjjV0dsJ/LMCINcxQueNFbUNQwvyD7Jk9ElaYnBUq50Eyxx1r03HKaTkDH/EK2Y0jlVMBTWYY9Jg=
  解密 → {"code":-3,"message":"Processing error","data":null,"promptInfo":null}
```

> 注意：**命中 Controller 的响应才加密**；404 / 网关错误是明文 JSON。
> 因此"状态码 + 是否密文"可以当**路由存在性探针**使用（本项目的路由枚举就是这么做出来的）。

## 1. Java 侧只有 JNI 桥

`com.android.auth.AuthUtil` 的全部字符串只有三条：

```
loadLibrary("safe_auth")
getEncodeText / getDecodeText / getRawSignedText
```

**dex 里没有任何密钥字符串** → 加密完全在 native。

## 2. JNINativeMethod 表重建（关键技巧）

`.data.rel.ro` 段读出全是 `0x0`，因为指针是 `R_AARCH64_RELATIVE` 重定位。必须解析 `.rela.dyn` 的 `r_addend` 才能还原：

```python
# .rela.dyn 里筛选落在 .data.rel.ro 的项
for i in range(0, len(rela_dyn), 24):
    off, info, addend = struct.unpack_from('<QQq', rela_dyn, i)
    # off = 目标地址, addend = 实际值（相对重定位）
```

还原后的表（`.data.rel.ro + 0x2d2a0`，每项 24 字节）：

| name | signature | impl |
|---|---|---|
| `nativeGetRawSignedText` | `(Ljava/lang/String;)Ljava/lang/String;` | `0x9e44` |
| `nativeGetEncodeText` | 同上 | `0x9fc4` |
| `nativeGetDecodeText` | 同上 | `0xa1cc` |

## 3. 为什么 BL 扫描找不到 AES 调用

`aes_key_setup` / `AES_CBC_PKCS7_Encrypt` 等是**导出符号**，编译成 PIC 后内部调用会走 **PLT**（可被符号插入），所以 `.text` 里根本没有指向它们的 `BL`。

正确做法：解 `.rela.plt` 建立 PLT stub ↔ GOT slot ↔ 符号名 的映射：

```
stub_addr = 0x21c90 + (got_slot - 0x265d8) / 8 * 0x10
```

得到：

| PLT | 符号 |
|---|---|
| `0x21ce0` | `time` |
| `0x21cf0` | `srand` |
| `0x21d00` | `rand` |
| `0x21d30` | `strlen` |
| `0x21f00` | **`AES_ECB_PKCS7_Encrypt`** |
| `0x21f10` | **`AES_ECB_PKCS7_Decrypt`** |

## 4. 三个 native 的实现

### `nativeGetEncodeText` → `0x9fc4`

```asm
009ff4  ldr  x8,[x8,#0x548]        ; JNIEnv->GetStringUTFChars
00a004  ldr  w8,[x8(=0x2db60)]     ; 初始化标志，必须 == 1
00a01c  ldr  x8,[x8,#0x520]        ; JNIEnv->GetStringLength
00a038  bl   0x21ce0               ; time(NULL)
00a03c  bl   0x21cf0               ; srand(t)
009...  loop:
00a048  mov  w24,#0xec4f / movk #0x4ec4   ; 0x4ec4ec4f = 除以 26 的魔数
00a04c  mov  w25,#0x1a             ; 26
00a058  bl   0x21d00               ; rand()
00a05c  smull/msub ...             ; w8 = rand() % 26
00a074  add  w8,w8,#0x41           ; 'A' + x
00a078  strb w8,[x26],#1           ; 覆写入参缓冲区
00a110  bl   0xcbd8                ; AES_ECB_PKCS7_Encrypt(...)
```

⇒ `getEncodeText(s)` 会**先把入参覆写成同长度的随机大写串**，再加密返回。
这是服务端要求的 "requestId 随机化" 语义，**不是**通用加密 API。

### `nativeGetDecodeText` → `0xa1cc` → `0xcd00`

```asm
00ccfc  bl   0xcac8               ; 取 key
00cd50  bl   0x21f10              ; AES_ECB_PKCS7_Decrypt(data, len, key, 16)
```

### `nativeGetRawSignedText` → `0x9e44` → `0xc080`

`0xc080` 解析入参 JSON（jsoncpp `0xd170`），然后**往 JSON 里注入 5 个自证字段**：

```
packageName  (字符串 @0x45f5)
appSign      (@0x4a1a)
apkSign      (@0x47d5)
appVersion   (@0x5243)
soMd5        (@0x4c17)
```

字段值来自 `SafeIOUtil.open(config)` 传入的配置（`Java_com_camerasideas_safe_SafeIOUtil_open` @ `0xa470` → `openAt` @ `0x21d60`）。

## 5. 密钥派生（`0xcac8` 完整反汇编）

```asm
00cadc  mov  w9, #0x6168              ; 'h','a'
00cae8  movk w9, #0x6168, lsl #16     ; 'h','a'  → w9 = "haha"
00cae4  strb wzr, [sp,#0x1d]          ; 结束符
00caec  strb w8(=8), [sp,#0x18]       ; libc++ SSO: byte0 = size<<1 → size = 4
00caf0  stur w9, [sp,#0x19]           ; data = "haha"
00caf4  mov  w0,#0x6c ; bl 0x21d10    ; operator new(108)  ← MD5_CTX 大小
00cb04  bl   0x176c4                  ; ctx.init(std::string&)
00cb0c  bl   0x1831c                  ; update + final
00cb18  bl   0x177d4                  ; 取 digest 指针
00cb20  mov  w0,#0x11 ; bl 0x21e00    ; new(17)
00cb28  ldr  q0, [x21]                ; 读 digest 前 16 字节
00cb30  strb wzr, [x0,#0x10]
00cb34  str  q0, [x0]                 ; 拷成 16 字节 key 并返回
```

⇒ `key = MD5("haha")[:16]`（MD5 天然 16 字节）。**没有任何签名/设备参与派生**，是固定全局常量。

## 6. 复现

```python
import base64, hashlib
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad, unpad

KEY = hashlib.md5(b"haha").digest()   # 4e4d6c332b6fe62a63afe56171fd3725

enc = lambda o: base64.b64encode(AES.new(KEY, AES.MODE_ECB).encrypt(pad(json.dumps(o).encode(), 16))).decode()
dec = lambda s: json.loads(unpad(AES.new(KEY, AES.MODE_ECB).decrypt(base64.b64decode(s)), 16))
```
