# 04 · 账号体系与额度

## 1. signIn 实为「开放注册」

参数校验链（服务端自描述，可直接当 schema 探针）：

```
packageName 缺失   -> -10001 "packageName 或者 bundleId不正确"
uuid 缺失          -> -10002 "uuid不正确"
accountId 缺失     -> -10003 "accountId 不正确"
appUserId 缺失     -> -10004 "appUserId 不正确"
signIn 缺 accountToken -> -10011 "accountToken 不正确"
```

**结论：`accountId` 由客户端自定义、`accountToken` 与 `verifyCode` 不做真实校验。**

```http
POST https://android.inshot.cc/api/iap3/user/signIn
Body(解密后):
{
  "packageName": "videoeditor.videomaker.aieffect",
  "uuid":        "<任意 uuid4>",
  "accountId":   "junk123",          // ← 客户端自定义
  "signType":    1,
  "accountToken":"t",                // ← 不校验
  "accountName": "n",
  "verifyCode":  "000000"            // ← 不校验
}

→ {"code":0,"message":"success",
   "data":{"appUserId":"FB9B1EFE2CAA67C77DAC35CD24",
           "accountId":"junk123","accountName":"n","isFirst":false}}
```

再传一次相同 `accountId` 会返回同一 `appUserId` 且 `isFirst:false` ⇒ 幂等注册。
换新 `accountId` ⇒ `isFirst:true` ⇒ 全新账号。

## 2. 额度体系

| 概念 | 说明 |
|---|---|
| `credits` | 通用点数，任务消耗 |
| `giftCredits` / `proGiftCredits` | 赠礼点数（`queryGiftCredits` 返回的是**赠礼目录**，不是余额） |
| `purchaseCredits` | 购买所得 |
| `frozenCredits` | 冻结中（任务进行中） |
| `hasPurchaseHistory` | 是否买过 |
| `accessFlags` | 能力开关串，如 `0501.9991.00101` |

商品额度（实测 `queryProductCredits`）：

| productId | credits |
|---|---|
| `credits_l1_v1` | 200 |
| `credits_l2_v1` … `l6_v1` | 递增（l4=+200 赠、l6=+2500 赠） |
| `videoeditor.videomaker.aieffect.monthly` | 800 / 月 |

## 3. 无免费额度（决定性验证）

| 检查 | 全新账号结果 |
|---|---|
| `signIn` | `code:0`，`isFirst:true` |
| `creditsBalanceCount` | `credits:0, giftCredits:0, purchaseCredits:0, hasPurchaseHistory:false` |
| `queryUnusedCount`（带 accessFlags） | `totalLimit:0, unusedCount:0, isLimitExceeded:false` |
| `querySubscriptionCredits` | `[]` |

⇒ **注册不赠送任何额度**；`queryGiftCredits` 里的 `credits:60 / expiredDays:30` 是"若发放赠礼则发多少"的模板。

## 4. 唯一缺口

`create`（唯一扣额度的动作）恒返回 `code:-2`。
资产/参数/身份均已验证正确（`query` / `cancel` 返回 `code:0`），因此可判定 `-2` = **额度不足**。

credits 可获取路径只有两条：

1. **Play IAP**：`createOrder` → Play 付款 → `verify`（带 `purchaseToken`）
2. **兑换码**：`/api/iap3/user/redeemCode`（需真实 code）

没有广告奖励、签到、注册赠送等免费接口（端点表中不存在此类路径）。

## 5. 账号与额度的耦合（对"号池"思路的结论）

- 账号可以**无限铸造**（`accountId` 自定义），但每个账号额度独立且为 0；
- 因此"多号池"在**没有额度来源**的前提下不产生任何可用能力；
- 若将来出现额度来源（购买/兑换），额度是**按 `accountId` 记账**的，无法跨号共享。
